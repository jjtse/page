湖倉調整－中台批次因應方案討論

湖倉年底後不再維護log_status table，需調整現行批次處理方式。

一、目前狀況

中台目前是每天固定時間執行，執行前會先確認湖倉資料是否已到齊，確認後才進行資料同步。

二、三個處理方案

方案作法異動程度
A. File Trigger湖倉資料到齊後通知中台執行。高
需拆分及調整現有批次
B. Log Center中台自行整理湖倉的資料到檔狀態，再依狀態執行。中
需新增程式及狀態表
C. 取消到檔檢查維持目前每天固定時間執行，但不再先確認湖倉資料是否到齊。低
主要取消既有到檔檢查

三、想討論：方案 C 是否可行？

簡單來說：現在是「時間到 → 檢查資料到齊 → 執行」，方案 C 改成「時間到 → 直接執行」。

資料還是每天會同步，主要差異是中台不再等待湖倉確認資料到齊。

優點

  • 改動最少，不需大幅調整現有批次。
  • 開發時間較短，較能配合年底時程。

需要接受的影響

  • 湖倉資料較晚到時，當次同步會有時間差。
  • 湖倉尚無新資料時，中台仍會執行，可能有部分無效運算。
時間差範例：
湖倉的 8/12 資料延遲到 8/13 09:00 才到，但中台已於 8/13 02:00 執行，因此 8/13 站台查到的仍會是 8/11 資料。
如果「資料可能有時間差」及「可能空跑」可以接受，是否可採方案 C，以降低本次修改範圍及年底時程風險？
